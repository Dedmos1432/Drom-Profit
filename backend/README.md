# Drom Profit Core Backend

FastAPI хранит анонимные выборки в файловой SQLite. API использует [общий OpenAPI v0.1.0](../shared/openapi.yaml) и [правила расчета](../docs/calculation-rules.md).

## Локальный запуск

Выполните команды из корня репозитория с Python 3.11 или новее.

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Swagger UI доступен по адресу [localhost:8000/docs](http://localhost:8000/docs), OpenAPI JSON — [localhost:8000/openapi.json](http://localhost:8000/openapi.json). Сервис читает контракт и демонстрационные данные из соседнего каталога `shared/`.

| Переменная | Значение |
|---|---|
| `DROM_DB_PATH` | Путь к SQLite. По умолчанию `backend/drom-profit.sqlite3`. Относительный путь отсчитывается от рабочего каталога, родительский каталог должен существовать. |
| `DROM_CORS_ORIGINS` | Точные разрешенные origins через запятую. Задайте, например, `http://localhost:5173` при локальной интеграции с Web. По умолчанию список пуст. |

Таблицы создаются при первом запуске. Данные и сессии сохраняются в том же файле между запусками. Стратегию миграций для последующих изменений схемы предстоит согласовать. Для публичного размещения API требуется HTTPS.

## Проверка через Swagger

1. Выполните `POST /api/session`. Введите полученный токен в **Authorize** без префикса `Bearer`. Клиент хранит токен между запусками для доступа к своей выборке.
2. Для демонстрационного предпросмотра отправьте `{"url":"https://auto.drom.ru/demo/1.html"}` в `POST /api/cars/import`. Результат с `source=demo` берется из [синтетических данных](../shared/fixtures/import-listings.json). Для сохранения отправьте подтвержденные данные в `POST /api/cars`. При ручном вводе передайте `source=manual`, `brand`, `model` и `price`.
3. Добавьте расходы, преимущества и заметки во вложенных маршрутах. Введите `amount: null` для неизвестной суммы и `amount: 0` для известной нулевой суммы. После проверки данных подтвердите рассмотренные категории через `PATCH /api/cars/{car_id}`.
4. Получите карточку и `GET /api/cars/{car_id}/summary`. Для сравнения отправьте минимум два уникальных ID своих карточек в `POST /api/comparison`.

Сравнение возвращает элементы в порядке запроса. При неполных данных разницы предварительные. При двойном учете оснащения разницы возвращаются как `null`. Для конфликтов факторов внутри одной карточки API возвращает `422` с кодами `duplicate_factor` или `conflicting_equipment`.

## Импортер

При сборке приложения подключите `create_app(importer=import_listing)`. Интерфейс — `async import_listing(url: str) -> ListingData` из `app.schemas`, ошибки — `ListingImportError` из `app.services.listing_import`. Допустимые коды и соответствующие HTTP-статусы заданы в общем контракте. Предпросмотр работает без записи в БД. В режиме по умолчанию используются три синтетических URL из fixtures, сетевые запросы отсутствуют.

## Тесты

Выполните команды из `backend/` в активированном окружении.

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Набор включает шесть общих расчетных векторов, HTTP-проверки контракта, валидацию, CRUD, сохранение после перезапуска, независимые сессии, полноту и демонстрационный импорт.

## Вопросы к следующей версии контракта

- Для сохраняемых целых чисел действует верхняя граница SQLite `2^63 − 1`. В OpenAPI v0.1.0 максимумы отсутствуют. При интеграции согласуйте диапазон денежных полей и результатов для точного чтения в обоих клиентах.
- Схема `Summary` передает статус полноты и итоговые суммы. Предупреждение `negative_adjusted_cost` передается в `Comparison.warnings`. Для отдельной карточки клиент может распознать отрицательный `adjusted_cost` по его значению. При необходимости отдельного предупреждения в саммари согласуйте расширение схемы.
