# Исследование: извлечение сведений из скачанных отчетов об истории автомобиля

Статус: исследовательская заметка, P1 по `docs/MVP.md`. **Обработка отчетов не реализована**
и не начинается до отдельного согласования. Реальные отчеты в репозиторий не кладутся.

## Цель

Пользователь загружает скачанный им отчет (PDF), сервер предлагает найденные сведения
как черновики заметок (`note kind = report`) или расходов. Пользователь подтверждает каждый
пункт. Автоматических штрафов, оценки ремонта и выводов о состоянии нет (`docs/MVP.md`).

## Необходимые образцы

Нужны согласованные и **обезличенные** образцы (VIN, госномер, ФИО, телефоны, адреса
замазаны или заменены):

1. По 3–5 отчетов каждого используемого провайдера (Дром и другие, если согласуем).
2. Разные случаи: «чистая» история; ДТП; ограничения или залог; расхождение пробега;
   такси или лизинг; несколько владельцев; импорт без истории в РФ.
3. Разные даты выпуска отчета — чтобы видеть изменения верстки.
4. Отчеты в виде PDF с текстовым слоем и, если встречаются, сканы или изображения.
5. Метаданные: провайдер, дата, способ получения (скачан из личного кабинета, распечатан в PDF).

Хранение: вне git, в согласованном закрытом хранилище команды. В тестах использовать
только синтетические PDF, собранные по образцу структуры.

## Потенциально извлекаемые сведения

| Сведения | Куда в продукте | Надежность |
|---|---|---|
| Марка, модель, год, объем, мощность | сверка с карточкой, расхождения как предупреждение | высокая |
| Количество владельцев, периоды владения | заметка | средняя |
| Записи о ДТП (дата, характер повреждений) | заметка; пользователь решает про расход | средняя |
| Ограничения, розыск, залог | заметка-предупреждение | высокая, если раздел есть |
| История пробега (дата — значение) | заметка; признак расхождения с объявлением | средняя |
| Использование в такси, лизинге, каршеринге | заметка | средняя |
| Отзывные кампании, сервисные записи | черновик расхода «maintenance» без суммы | низкая |
| Прошлые объявления (цена, дата) | заметка | низкая |

Суммы ремонта не извлекаются и не оцениваются: пользователь вводит их сам.

## Возможная реализация

1. `POST` загрузки файла (контракт и хранение — согласование с Core Backend), лимит размера
   (например, 10 МБ), проверка сигнатуры `%PDF-`, обработка в памяти без сохранения файла.
2. Извлечение текста библиотекой для PDF (кандидаты: `pypdf` — чистый Python;
   `pdfplumber`/`pdfminer.six` — точнее с таблицами). Новая зависимость — через владельца Core.
3. Определение провайдера и версии шаблона по устойчивым заголовкам; для каждого шаблона —
   отдельный парсер разделов с регулярными выражениями и тестами на синтетике.
4. Результат: список черновиков `{section, text, date?, value?, confidence}`; без подтверждения
   пользователя в карточку ничего не попадает.
5. Неизвестный шаблон → понятная ошибка и ручной ввод, а не «догадки».

## Технические ограничения и риски

* **Персональные данные.** VIN, госномер, ФИО прежних владельцев. Нужны минимизация,
  обработка без сохранения файла, отсутствие PDF и текста в логах, удаление по запросу.
* **Права и условия провайдеров.** Отчет куплен пользователем; допустимость автоматической
  обработки и показа сведений нужно проверить по условиям провайдера.
* **Нестабильная верстка.** Шаблоны меняются без уведомления; нужны версии парсеров и тесты.
* **Качество PDF.** Таблицы разваливаются при извлечении текста; сканы требуют OCR —
  тяжелая зависимость, вне MVP.
* **Безопасность файлов.** Вредоносные PDF (бомбы распаковки, глубокая вложенность, JavaScript):
  ограничения размера, числа страниц и времени обработки; обработка в отдельном процессе с лимитами.
* **Интерпретация.** Наличие ДТП не означает конкретный ремонт; продукт не делает выводов за пользователя.
