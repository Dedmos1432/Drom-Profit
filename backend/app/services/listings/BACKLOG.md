# Бэклог импорта объявлений

Статусы относятся к локальному коду этапа 7.2. Реальный источник и сквозной
маршрут Core Backend требуют отдельных проверок.

| Задача | Статус | Приоритет | Зависимости | Критерий готовности |
|---|---|---|---|---|
| PARSER-01 — Нормализация единиц | Реализовано и проверено локально | P0 | №4, разрешённые образцы для проверки форматов | Известные единицы пробега, объёма и мощности приводятся к схеме. Мили, неизвестные единицы и противоречия дают `null` |
| PARSER-02 — Валюта | Реализована консервативная политика | P0 | №4, условия реального источника | Цена возвращается только для явной `RUB`/`RUR`. Правило для формата без валюты требует подтверждения источником |
| PARSER-03 — Общий таймаут | Реализовано и проверено локально | P0 перед реальным режимом | №4, №3 для приёмки окружения | Очередь и сеть делят общий срок. Зависший процесс завершается. Отмена клиента сохраняет занятый слот до завершения процесса |
| PARSER-04 — HTTP-ошибки | Реализовано и проверено локально | P0 | №4, №3 для маппинга API | HTTP-статус классифицируется до чтения тела ошибки. Все пять кодов сохраняются |
| PARSER-05 — Точные хосты | Настройка реализована, список ожидает согласования | P0 перед реальным режимом | №4, команда, ответственные за доступ | Входные и редирект-хосты согласованы. Пустая настройка блокирует включение, шаблоны отклоняются |
| PARSER-06 — Данные запрошенного объявления | Реализовано и проверено на синтетике | P0 перед реальным режимом | №4, PARSER-10 и PARSER-11 | Объект и предложение выбираются однозначно по подтверждённому ID/URL. Связь сверена на разрешённой разметке |
| PARSER-07 — Главное фото | Реализовано и проверено на синтетике | P0 | №4, права и разрешённые образцы фото | Первый допустимый структурированный снимок или запасной `og:image`. Отсутствие даёт `null` |
| PARSER-08 — Дополнительные фото | Внутренний список проверен, публикация ожидает согласования | P1 | №3, №4, Web, Android, доступ к фото | Согласованный `image_urls`, исходный порядок, уникальные адреса, главное фото первым и совместимость с `image_url` |
| PARSER-09 — Рыночная оценка | Ожидает подтверждённого поля источника | После PARSER-10 | №4, ответственные за источник | Публичная оценка подтверждена на образцах и передаётся в рублях. До этого `null` |
| PARSER-10 — Согласование реального источника | Открыто | P0 перед реальным режимом | Команда и ответственные за доступ, №4 | Подтверждены API или HTML, допустимые хосты, редиректы, лимиты, поля, права на фото |
| PARSER-11 — Проверка на реальных объявлениях | Открыто, подготовлена матрица | P0 перед реальным режимом | PARSER-05, PARSER-10, №4 | Пройдены согласованные образцы с десктопной и мобильной разметкой, включая частичные и снятые карточки |
| PARSER-12 — Интеграция с Core Backend | Demo подключён. Интеграционные тесты пройдены | P0 | №3, №4, Xolopenya | Все три demo-превью возвращают 18 полей. Проверены Bearer, коды ошибок, сохранение отдельным запросом и изоляция сессий |

## Матрица ссылок для согласования с Web и Core

| Вход | Ожидаемое поведение парсера |
|---|---|
| HTTPS, точный хост, корректный путь `*.html` | Допускается к поиску fixture или к запросу настроенного провайдера |
| `?query` и `#fragment` | Исключаются из ключа и сетевого адреса. Регистр хоста приводится к нижнему |
| `http`, явный порт (включая 443), credentials, IP, корневой домен, неизвестный хост | `invalid_url` |
| Пустая строка, синтаксически неверный URL, главная, путь каталога без `.html` | `invalid_url`. Core возвращает `400` для некорректной строки и `422` для отсутствующего поля или неверного типа |
| Синтаксически подходящий URL на demo-хосте без записи | `listing_unavailable` |
| Редирект на другой хост | Только точный хост из согласованного списка целей. Исходный числовой ID сохраняется. Без числового ID канонический URL должен совпадать |

На этапе 8.3 Web и Mock согласованы с demo-правилами Parser. Web проверяет
HTTPS, точный хост и путь объявления по исходной строке. Mock канонизирует
хост и отбрасывает query и fragment при поиске. В режиме `real` эти преобразования
выполняет Parser. Витрина `101–105` и специальные тестовые ответы остаются в Mock.
Синхронизация Android и будущие правила согласованных хостов ведутся в INT-07.
Матрица REST проверена в Linux. Связанные задачи — INT-02, INT-03, INT-07 и INT-15 в [интеграционном бэклоге](../../../../docs/INTEGRATION_BACKLOG.md).

## Приёмочные образцы

| Образец | Ожидаемая проверка |
|---|---|
| Обычная карточка | Совпадают ID, ссылка, марка, модель, год, рублёвая цена и пробег |
| Несколько фото | Порядок, дубли, невалидный первый URL, доступность и срок жизни адресов |
| Неполная карточка | Отсутствующим значениям соответствует `null`. Уточнить валюту и единицы, если у них отсутствует явное обозначение |
| Бензин, дизель, гибрид, электро | Верные типы двигателя и единицы, отсутствие неприменимых характеристик |
| Разные комплектации | Извлечённая комплектация относится к выбранной карточке |
| Страница с похожими автомобилями или несколькими предложениями | Извлекается только подтверждённый объект и относящееся к нему предложение |
| Снятая карточка | `listing_unavailable` для подтверждённого статуса, HTTP 404/410 или известного перенаправления |
| Недоступная карточка | Различаются ограничения доступа, поломка источника и отсутствие объявления |
| Десктоп и мобильная версия | Сопоставляется структура, ID, URL, поля, особенности редиректов и отсутствие структурированных данных |
| Опубликованная рыночная оценка и карточка без неё | После согласования подтверждается отдельное поле и его валюта. При отсутствии оценки возвращается `null` |

До получения разрешённых образцов эти случаи проверяются только локально с
синтетической разметкой и подставными сетевыми ответами.
