# Дизайн-система Drom Profit Web

**Утверждено для P0.** Значения ниже — решения Drom Profit Web. Измеренные свойства оригинального интерфейса и выводы из наблюдений зафиксированы отдельно. [Аудит](DROM_VISUAL_AUDIT.md) хранит измерения и ограничения. [Токены](design-tokens.json) задают числовые значения и цвета, [спецификация компонентов](UI_COMPONENTS.md) — их применение. Приложение использует эти токены через сгенерированные CSS-переменные.

## Принципы

- Сохранить характерные для веб-версии Дрома светлые нейтральные поверхности, синие ссылки, явную иерархию цены и характеристик, компактные строки с разделителями и умеренное скругление. Красный остаётся компактным бренд-акцентом. Основные действия используют синий.
- Вести пользователя от выбранного автомобиля к его расчётным показателям. Название, цена объявления, полнота сведений и действия имеют постоянный порядок чтения.
- Начинать с P0 и одинаково представлять факторы и статусы на карточке и в сравнении. Сайт использует собственные стили, шрифтовый стек, иконки и компоненты.
- Обозначать важные состояния сочетанием подписи, структуры, контраста и при необходимости иконки. Цвет дополняет смысл.

Палитра светлая. У обследованных страниц есть тёмные варианты. Светлая тема — единственная тема P0.

В продуктовых маршрутах основной фон — `color.semantic.background.surface`. Светло-серый `color.semantic.background.panel` применяется к панелям быстрого добавления и импорта. Строки выборки остаются плоскими, с фото слева и отдельным ценовым блоком справа на широком экране. Секции отделяются отступами и линиями. Dev UI Kit сохраняет фон `color.semantic.background.page`.

## Отступы, размеры и поверхности

Шкала `spacing` содержит 2, 5, 10, 12, 15, 20, 24, 30 и 40 px. Использовать 5–10 px между иконкой и подписью, 10–15 px между соседними полями и строками, 15–20 px на внутренних полях карточки, 24–30 px между секциями и 40 px между крупными группами. На компактной ширине панель и карточка используют уменьшенный отступ 15 px.

- Поля и обычные кнопки от 40 px по высоте при точном указателе. Большая кнопка 50 px. Цель тач-взаимодействия от 44×44 px, включая компактную кнопку с иконкой. Высота может расти с переносом текста и пользовательским масштабом.
- Контуры 1 px, контур фокуса и индикатор выбранной вкладки 2 px. Базовое скругление кнопки, поля и изображения — 12 px. Служебные карточки — 16 px, крупные функциональные панели и диалоги — до 24 px. Плашки округляются полностью.
- Карточки и секции плоские. Тень `shadow.overlay` применяется к раскрывающимся панелям и диалогу. Границы остаются различимыми при отсутствии тени.

## Сетки и адаптивность

Пороговые значения — проектные. Единица измерения относится к CSS viewport. Основной контейнер до 1120 px по содержимому с боковыми полями, ширина формы до 640 px, диалога до 480 px. Компоновка растёт до доступной ширины. В проекте проверять 390, 768, 1024, 1280, 1440 и 1920 px, а для проверки reflow дополнительно 320 CSS px.

| Ширина      | Контейнер и компоновка                                                                                                                                                |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| До 599 px   | Поля страницы 16 px. Формы, основные действия и секции в одну колонку. У карточки компактное фото и растущее текстовое поле. Кнопки и метки не перекрывают содержимое |
| 600–899 px  | Поля 24 px. По необходимости два коротких связанных поля в ряд. Карточка остаётся линейной, детали и саммари идут последовательно                                     |
| 900–1199 px | Поля 24 px. Детали могут использовать 3:2 с правой колонкой не уже 300 px. Между колонками `spacing.panel`. Основные действия остаются в естественном порядке DOM     |
| От 1200 px  | Поля 32 px и ограничение ширины основного контейнера. Денежный блок и характеристики видны в одной части страницы, если позволяет контент                             |

Для будущего сравнения ширина колонки подписи от 136 px, столбца автомобиля от 152 px. В текущем UI Kit компонент Table показывает локальную прокрутку на образце шириной от 660 px. Таблица сохраняет все выбранные автомобили. Если она не помещается, прокручивается собственная подписанная область, а страница сохраняет свою ширину. Первая колонка может закрепляться при условии, что не перекрывает фокус и оставляет место для значения. Таблица должна читаться с горизонтальной прокруткой на тач-экране и с клавиатуры. Короткая подсказка о прокрутке показывается только при переполнении. Не обрезать значения и не превращать каждый столбец машины в независимую таблицу.

## Иконки и визуальные состояния

Использовать компактный согласованный набор собственных иконок или независимый набор с проверенной лицензией. Размер по умолчанию 20 px, вспомогательный 16 px, крупный 24 px. Для контуров базовый штрих 2 px, цвет `currentColor`. При текстовой подписи декоративная иконка скрывается от ассистивных технологий. Иконка как единственная метка действия требует доступного имени.

| Состояние       | Правило                                                                                                                                            |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Default         | Явная визуальная роль, читаемый текст, доступное имя                                                                                               |
| Hover           | Изменение заливки, границы или оформления ссылки при наличии указателя                                                                             |
| Active          | Тон активного нажатия. Выбор варианта отражается отдельно в selected                                                                               |
| Focus-visible   | Контур сохраняется при `hover` и при ошибке поля. Для элементов внутри таблицы и диалога проверять обрезание контура                               |
| Disabled        | Семантика `disabled` или обоснованное `aria-disabled`, блокировка действия. Причина рядом, если её нельзя вывести из контекста                     |
| Selected        | Цвет, подпись или знак и соответствующая разметка `checked`, `aria-pressed`, `aria-selected` или `aria-current` по типу контрола                   |
| Loading         | Сохранять подпись и ширину действия, показывать текст ожидания. На области результата допустим `aria-busy`, декоративный skeleton скрыт от диктора |
| Error / success | Состояние имеет текст и понятное следующее действие, когда оно существует. Значимая информация остаётся в области, где возникло событие            |

Переходы 150 ms `ease-out` только для обратной связи. Вращение индикатора загрузки передаёт рабочее состояние. При `prefers-reduced-motion: reduce` использовать `motion.reduced` и статичный индикатор загрузки вместе с текстом. Переходы не должны задерживать управление.

## Доступность

- Цель — WCAG 2.2 AA. Контраст обычного текста минимум 4,5:1, крупного текста и значимых визуальных границ интерактивных элементов минимум 3:1. Проверять фактические пары на всех используемых фонах и состояниях. [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- Семантические заголовки, `lang="ru"`, доступные названия полей и действий, нативные кнопки и формы по возможности. Сообщения об ошибках связывать с полями через `aria-describedby` и `aria-invalid`, сохраняя видимую метку. Для общего ответа API показывать сообщение формы, когда поле определить нельзя.
- Полный сценарий доступен с клавиатуры. Фокус виден, не закрывается прилипающей панелью и возвращается к вызывающему элементу при закрытии диалога. При удалении вызывающего элемента переводить фокус на следующую карточку или логически следующий контрол.
- Уведомления, меняющиеся без смены фокуса, сообщать через `role="status"`, а срочные блокирующие ошибки через `role="alert"` без повторного чтения каждого ряда. Скринридер получает подпись, сумму, валюту и статус в естественном порядке.
- Проверить увеличение текста, reflow, контраст, клавиатуру, touch и скринридер вручную при реализации. Таблица сохраняет нужную горизонтальную прокрутку в собственной области.

## Денежные показатели и полнота

Формат — целые рубли в `ru-RU`, например `1 250 000 ₽`. Выводить серверные суммы и статусы. Сценарий сравнения использует серверные `items`, `warnings` и `provisional`. Правила данных закреплены в [экономической модели](../../docs/calculation-rules.md) и [контракте](../../shared/openapi.yaml).

| Показатель / состояние                 | Правило отображения                                                                                                                                                                                                                       |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Цена объявления                        | «Цена объявления» рядом с автомобилем, исходное число `listing_price` или `Car.price`                                                                                                                                                     |
| Рыночная оценка Дрома                  | Подпись «Рыночная оценка Дрома» в блоке сведений об объявлении с указанием источника. При `null` — «Нет данных» там, где показывается поле                                                                                                |
| Расходы / преимущества                 | «Необходимые вложения» и «Ценность преимуществ». По возможности показать групповой статус и число неизвестных сумм. Не маскировать неполноту нулём                                                                                        |
| Предполагаемые затраты на приобретение | Отдельная строка `acquisition_cost`, при нужде короткая подпись «Цена объявления и учтённые вложения»                                                                                                                                     |
| Скорректированная стоимость            | Отдельная строка `adjusted_cost` в саммари, с пояснением «Условный показатель для сравнения». Отрицательное значение отображается со знаком                                                                                               |
| Разница                                | «Разница с минимальной скорректированной стоимостью». При равенстве допускаются несколько нулей. Ноль не даёт статуса рекомендации к покупке                                                                                              |
| Неизвестно / ноль                      | Для неизвестной суммы фактора явно выводить «Не указано». `0 ₽` означает известное число. Если сервер вернул 0 как сумму известных значений при неполных сведениях, подписать «По указанным суммам» и оставить видимым статус неполноты   |
| Неподтверждённые группы                | Раздельные подписи и отдельные действия проверки расходов и преимуществ. При изменении показывать возвращённые сервером флаги и обновлённое саммари                                                                                       |
| `incomplete` / `provisional`           | Оставить видимыми доступные суммы и указать предварительность возле итога и разниц. Сообщение поясняет, в какой группе не хватает данных. Не выделять окончательного победителя                                                           |
| `double_count`                         | Текст «Одно оснащение учтено и как расход, и как преимущество». Если известен фактор, указать его понятное название. Для `difference_from_min: null` пояснить «Разница недоступна до исправления». Остальные переданные суммы сохраняются |
| `negative_adjusted_cost`               | Показать переданное сервером значение и текст «Проверьте ценность преимуществ». Одиночный `Summary` не передаёт код предупреждения. Представление этого предупреждения отдельно от сравнения требует согласования                         |
| Ошибка импорта                         | Показать читаемое сообщение рядом со ссылкой, оставить введённые данные и дать доступ к ручному вводу. Demo-источник обозначать текстом в предпросмотре и сохранённой карточке                                                            |

## Применение

Начинать с компонентов, нужных четырём экранам P0. Модифицировать существующий компонент через семантический вариант, когда контракт и поведение совпадают. Новые решения фиксировать в спецификации и токенах. При расхождении UI с API уточнять серверное поведение по контракту, фикстурам и владельцу backend.

Файл токенов использует листья `$type` / `$value`. Ссылка вида `{color.palette.red}` указывает на путь листа. Генератор `npm run tokens:generate` пропускает `$meta`, создаёт kebab-case переменные с префиксом `--dp-` и разворачивает ссылки в `var(...)`. Он генерирует медиаправила для общих ролей контейнера и типографики. Для структурных медиаправил в CSS Modules используются те же числовые пороги, потому что CSS custom properties не разрешаются в условиях обычных медиазапросов.
