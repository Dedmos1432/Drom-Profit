# Интеграция Web с Backend

Web P0 подключён к интеграционному Backend. Режим `real` использует Core и PostgreSQL, а импорт обслуживает Demo Parser. Режим `mock` остаётся доступен для независимой разработки. [OpenAPI](../../shared/openapi.yaml) · [Расчётные fixtures](../../shared/fixtures/calculation-tests.json)

## Действующий контракт

| Метод              | Путь                                        | Использование                                                                                             |
| ------------------ | ------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| POST               | `/api/session`                              | Создание анонимной сессии, получение Bearer-токена                                                        |
| GET                | `/api/cars`                                 | Выборка и метаданные для сравнения                                                                        |
| POST               | `/api/cars/import`                          | Предпросмотр импорта                                                                                      |
| POST               | `/api/cars`                                 | Сохранение подтверждённого пользователем автомобиля                                                       |
| GET, PATCH, DELETE | `/api/cars/{car_id}`                        | Карточка, характеристики, флаги подтверждения и удаление                                                  |
| GET                | `/api/cars/{car_id}/summary`                | Саммари автомобиля для карточки и выборки                                                                 |
| POST               | `/api/cars/{car_id}/{collection}`           | Добавление записи, где коллекция — `expenses`, `benefits` или `notes`                                     |
| PATCH, DELETE      | `/api/cars/{car_id}/{collection}/{item_id}` | Изменение и удаление записи в каждой из трёх коллекций                                                    |
| POST               | `/api/comparison`                           | Запрос `{ car_ids }` для двух или более уникальных ID. Ответ содержит `items`, `warnings` и `provisional` |

Защищённые операции используют `Authorization: Bearer …`. Backend проверяет принадлежность всех объектов токену и возвращает `404` для чужих и отсутствующих ID, `401` для недействительного токена. Ошибки передаются как `{ code, message }`, успешное удаление — как `204`. Ошибки импорта переводятся в пользовательские состояния. Для сетевых сбоев и ошибок чтения доступна ручная повторная попытка. Для мутаций форма сохраняет введённые значения.

`Summary` возвращает целые рубли, счётчики неизвестных сумм и статус полноты. В `Comparison` каждому `car_id` соответствует `difference_from_min`. При двойном учёте разницы по всем машинам равны `null`. Предусмотренные предупреждения — `incomplete`, `double_count` и `negative_adjusted_cost`. UI сохраняет порядок `items`, связывает данные по ID и отображает переданный флаг `provisional`.

## Конфигурация и CORS

Локальная интеграция использует `VITE_API_MODE=real`, `VITE_API_BASE_URL=http://127.0.0.1:8000` и `DROM_CORS_ORIGINS=http://localhost:5173`. В URL сервера префикс `/api` задаёт HTTP-клиент. MSW запускается только в `mock`. HTTP-ошибка или сбой сети остаётся ошибкой в интерфейсе. Для сборки задайте переменные до `npm run build`. [Команды общего запуска](../../docs/INTEGRATION_RUNBOOK.md)

При разных origin backend должен пропускать preflight `OPTIONS` и разрешить точный origin фронтенда, методы `GET`, `POST`, `PATCH`, `DELETE` и заголовки `Authorization`, `Content-Type`, `Accept`. Для доступа с HTTPS-страницы нужен HTTPS endpoint. Браузер восстанавливает токен из локального хранилища. Ключ включает режим, сценарий и адрес сервера. При `401` пользователь явно начинает новую сессию, после чего клиент очищает токен, состав сравнения и прежний кэш запросов.

## Импорт

Для интеграционной сборки Web проверяет HTTPS, точный хост `auto.drom.ru`, путь с `.html` и отсутствие credentials и явного порта. В сегментах пути допускается `~`, подтверждённый на сохранённом объявлении. Проверка выполняется над исходной строкой до нормализации. В `real` запрос сохраняет исходное значение, канонизацию выполняет Parser. Сетевой стенд использует тот же Web-режим `real`, а источник выбирается в Backend. Mock для поиска приводит регистр хоста к нижнему, убирает query и fragment и различает `400 invalid_url`, `404 listing_unavailable` и `422 validation_error`. [Сетевой стенд](../../docs/LIVE_LISTING_VALIDATION.md)

Backend обслуживает три общие ссылки `/demo/1.html`–`/demo/3.html`. Дополнительные адреса `/demo/101.html`–`/demo/105.html` доступны через Web Mock. При ошибке повторного импорта Web сохраняет предыдущий редактируемый предпросмотр и показывает, к какой ссылке он относится. Ошибка сети предлагает явный повтор или переход к ручному вводу.

## Расхождения и текущие решения Mock API

- Правила расчёта связывают предварительные разницы с неполнотой. Fixtures дополнительно ожидают `provisional: true` при отрицательной стоимости и двойном учёте даже у полных карточек. OpenAPI задаёт булево поле без условия. Mock следует fixtures. При конфликте разницы равны `null`, при отрицательной стоимости остаются числовыми.
- `Summary` не содержит `warnings`. Для отрицательного значения карточка показывает пояснение по числу из ответа. `Comparison` использует коды предупреждений API. У `Warning` нет `car_id`, а опциональный `factor_key` позволяет связать конфликт с записями в выбранных карточках.
- С OpenAPI 0.2.0 Web и Mock используют единый предел 1 трлн ₽ для цены, оценки, фактора и суммы каждой группы. Web проверяет исходные токены денежных ответов через `lossless-json` и отклоняет недопустимые значения до кэша. Mock проверяет диапазоны и агрегаты при записи. `422 amount_out_of_range` отображается с указанием ограничения и сохраняет форму. Сетевые денежные операции не повторяются автоматически. [Денежный контракт](../../docs/MONEY_CONTRACT.md) · [Общие денежные проверки](../../shared/fixtures/money-contract-tests.json)

## Открытые вопросы

- Каков срок действия токена и возможна ли безопасная процедура восстановления прежней анонимной выборки после `401`?
- Справочник и единая нормализация необязательного `factor_key` отложены до пост-MVP. Расходы и преимущества вводятся свободно. Mock API обрезает крайние пробелы и возвращает `400` для конфликтов внутри карточки. Core возвращает `422 duplicate_factor` или `422 conflicting_equipment`. Web показывает объяснение по коду. При двойном учёте между карточками Comparison возвращает `double_count`.
- Нужны ли структурированные предупреждения для `Summary`, ID затронутых автомобилей и формальные условия `provisional`?

### Фотографии объявлений

Начиная с OpenAPI 0.3.0, `real` и `mock` передают `image_urls` в предпросмотре и детальной карточке. Оба режима используют существующий `VehicleGallery`. Список и таблица сравнения берут `image_url`. Web проверяет ссылки перед кэшированием и показывает старый ответ с одним `image_url`. При недоступности одного снимка оставшиеся доступны для выбора. Миниатюры загружаются лениво.

В demo пути начинаются с `/demo/vehicles/` и разрешаются относительно статических ресурсов Web. Три общих объявления используют `shared/fixtures/import-listings.json`. Пять карточек Showcase возвращают массивы через обычный Mock API. [Режимы запуска, безопасность и совместимость](../../docs/PHOTO_GALLERY_CONTRACT.md)

## Возможные улучшения

- Согласовать идемпотентность записывающих POST. При сетевом сбое клиент может не знать, успел ли сервер сохранить запись. `POST /api/comparison` используется как чтение результата и безопасен для повтора.
- Измерить загрузку длинных выборок. Сейчас для саммари используется отдельный GET на автомобиль. Пакетное саммари имеет смысл при заметной нагрузке либо задержке.
