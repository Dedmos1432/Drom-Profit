# Визуальный аудит веб-версии Дрома

Дата наблюдений — 24 ноября 2026 года. Область применения — интерфейс Drom Profit Web в пределах P0. Проектные значения собраны в [дизайн-системе](DESIGN_SYSTEM.md).

## 1. Цель и маркировка

- **Measured** — значение из Chrome `getComputedStyle()`, `getBoundingClientRect()`, вычисленного custom property, DOM или измерения viewport. Цвета записаны в HEX или RGBA. Прозрачность учитывается при чтении цвета поверх фона.
- **Inferred** — вывод из нескольких страниц, скриншотов или замеров. Мотив выбора конкретного оформления и назначение неиспользованного CSS-свойства к измерениям не относятся.
- **Proposed** — решение для Drom Profit Web. На него не следует ссылаться как на свойство Дрома.

## 2. Инструменты

Встроенный Chromium в Codex, Browser MCP, Playwright API для чтения DOM и вычисленных стилей, управление viewport и просмотр снимков. В DOM проверялись видимые контролы, их роли, семантика таблиц, размеры, стили псевдоэлементов и вычисленные CSS-переменные корня. Клавиатурные и pointer-действия ограничивались публичными формами и сравнением каталога.

Отдельный временный профиль Chrome с DevTools Protocol использовался для PNG-снимков в светлой теме и проверки мобильного варианта. Установлены viewport 390×844, Android user agent и touch-эмуляция. Измерялись только публичные элементы, пропускалась передача VIN, контактов и содержимого полей.

## 4. Viewport

LIST, XTR и CMP-2 проверены при 1920×1080, 1440×900, 1280×800, 1024×768, 768×1024 и 390×844 CSS px с десктопным user agent. HOME, CAT, SEARCH, VIN, WISH, OUT и вход CMP дополнительно проверены при 1280×720. В десктопной конфигурации `innerWidth` и `clientWidth` отличаются примерно на 15 px при вертикальной полосе прокрутки. LIST, XTR и CMP-2 также проверены с эмулированным мобильным профилем при 390×844. Размеры округлены до десятых и приведены в CSS px.

## 8. Layout и сетки

**Measured.** При 1440×900 левый край основной секции LIST, XTR и CMP-2 находится примерно на x=99,4 px, при 1920×1080 — x=339,4 px. Ширина секции около 966 px. При 1280×800 левый край x=20 и ширина около 964,8 px. При 1024×768 левый край x=20 и ширина 724 px. В XTR на 1440×900 левая колонка галереи 579,6 px, правая колонка характеристик 366,4 px, промежуток 20 px. В CMP-2 данные разложены в div/flex-строки с повторением ширины 161 px на автомобиль. Метка строки располагается над значениями. В SEARCH результат — нативная таблица с 6 колонками в просмотренной выдаче. В XTR таблица характеристик — две колонки. Навигационная ссылка на верхней полосе LIST и XTR высотой 50 px с горизонтальным padding 10 px. Хлебные крошки XTR начинаются на y=70 px.

**Inferred.** Большая ширина видимой страницы включает области вокруг основной секции. Фиксировать 966 px как универсальную ширину всего документа было бы неверно. У страницы сравнения сильная привязка названий параметров к группам и общим вертикальным линиям автомобилей.

## 9. Иконографика

**Measured.** XTR 1440×900, иконка у действия «Поделиться объявлением» — SVG 20×20 px при высоте действия 24,8 px, цвет текста действия `#1A76CB`. CMP-2 1280×720, видимые SVG кнопок переключения — 10×20 px, стрелка выбора — 10×6 px. На стрелке использована заливка `#6C757F` без stroke. Вычисленные свойства контейнера SVG сами по себе не дают визуальную толщину линий, поэтому общая толщина штриха не установлена.

**Inferred.** Простые геометрические очертания, маленькая стрелка выбора и цвет иконки, связанный с ролью действия, повторяются в формах и деталях.

**Proposed.** Собственные монохромные иконки с `currentColor`, обычно 20 px, с масштабом 16/24 px и штрихом 2 px для контурных иконок. Компактный знак внутри кнопки сохраняет размер области нажатия кнопки. Исходные SVG не требуются.

## 13. Выявленные закономерности

- **Inferred.** Нейтральные поверхности и тонкие разделители хорошо отделяют повторяющиеся данные. Декоративные тени редки и заметнее на раскрытых контролах.
- **Inferred.** Цена, название автомобиля и характеристики имеют разные уровни иерархии. Город и оценки присутствуют рядом, но выделены размером, текстом или отдельной плашкой.
- **Inferred.** У сравнения общая структура строк и колонок, а в карточке характеристики компактно выстроены парами. Это разные способы чтения одних и тех же атрибутов.

### Повторение в Chrome DevTools

1. Откройте LIST, XTR, CMP-2, SEARCH и VIN из таблицы источников. Установите нужную тему и размер в Device Toolbar. Для мобильной проверки выберите профиль телефона и перезагрузите страницу один раз. Запишите `innerWidth`, `clientWidth`, `scrollWidth`, тему и видимый вариант страницы.
2. В Elements выберите конкретный элемент. Для `hover`, `active` и `focus-visible` используйте кнопку `:hov`. Отдельно пройдите форму клавишей Tab, чтобы увидеть реальный порядок и поведение фокуса. Для перехода размера последовательно сузьте окно между 1024 и 1280 px.
3. Скопируйте пары «источник и элемент → состояние → вычисленные стили», либо запустите фрагмент ниже для выбранного в Elements элемента. Для внешних материалов используйте обрезку области без контактов и персональных данных. Для продолжения нужны замеры фильтра LIST, сетки XTR, контейнера CMP-2 и хотя бы по одному состоянию поля, кнопки и уведомления, которое удаётся воспроизвести в публичном интерфейсе.

```js
(() => {
  const element = $0;
  if (!(element instanceof Element)) return "Выберите элемент в Elements";

  const properties = [
    "color", "background-color", "font-family", "font-size", "font-weight",
    "line-height", "letter-spacing", "font-variant-numeric", "padding", "margin",
    "gap", "width", "min-width", "max-width", "border", "border-radius",
    "box-shadow", "outline", "outline-offset", "display", "position",
    "grid-template-columns", "overflow-x", "transition-property",
    "transition-duration", "animation-duration", "fill", "stroke", "stroke-width"
  ];
  const keys = [
    "--drom-brand", "--background-page", "--background-primary", "--text-primary",
    "--text-secondary", "--control-hover-border", "--blue-button-bg",
    "--blue-button-hover", "--red-button-bg", "--red-button-hover",
    "--invalid-element-on-form-bg", "--background-warning", "--background-success"
  ];
  const root = getComputedStyle(document.documentElement);
  const styles = getComputedStyle(element);
  const { width, height } = element.getBoundingClientRect();
  return {
    origin: location.origin,
    viewport: {
      width: innerWidth,
      height: innerHeight,
      clientWidth: document.documentElement.clientWidth,
      scrollWidth: document.documentElement.scrollWidth
    },
    node: element.tagName.toLowerCase(),
    size: { width, height },
    states: Object.fromEntries(
      [":hover", ":active", ":focus", ":focus-visible", ":disabled", ":checked"]
        .map(state => [state, element.matches(state)])
    ),
    styles: Object.fromEntries(properties.map(key => [key, styles.getPropertyValue(key)])),
    tokens: Object.fromEntries(keys.map(key => [key, root.getPropertyValue(key).trim()]))
  };
})();
```

Скрипт читает размеры, состояние выбранного узла и заданный список свойств. Он не читает содержимое полей, хранилища и cookies и не отправляет сетевые запросы. Код предпочтительно запускать как Snippet или в Console через разрешённый рабочий процесс браузера.

## 15. Рекомендации для Drom Profit

| Экран | Proposed |
|---|---|
| Моя выборка | Использовать компактный повторяемый автомобильный ряд с фото, названием, ценой и подписью статуса. На мобильном держать выбор для сравнения доступным без горизонтальной прокрутки. Пустая выборка ведёт к добавлению автомобиля |
