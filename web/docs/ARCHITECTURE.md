# Архитектура Drom Profit Web

## Стек и слои

React, TypeScript в строгом режиме, Vite и React Router. Визуальные компоненты используют CSS Modules, общие CSS-переменные и Lucide. TanStack Query хранит серверные данные, React Hook Form и Zod обслуживают формы. MSW отвечает за Mock API.

| Каталог                    | Ответственность                                                                                                 |
| -------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `src/main.tsx`, `src/app/` | Конфигурация, запуск MSW, QueryClient, маршруты и общий layout                                                  |
| `src/pages/`               | Выборка, добавление, карточка, сравнение, 404 и development UI Kit                                              |
| `src/entities/session/`    | Восстановление токена, создание сессии и граница защищённых маршрутов                                           |
| `src/entities/vehicle/`    | Типизированные операции, ключи запросов, централизованное обновление кэша, валидация и представление автомобиля |
| `src/entities/comparison/` | Типы, ключи и чтение результата Comparison                                                                      |
| `src/features/`            | Импорт, общая форма автомобиля, управление расходами, преимуществами и заметками, удаление с подтверждением     |
| `src/widgets/`             | Шапка, строка выборки, разделы рабочей области, саммари и таблица сравнения                                     |
| `src/shared/`              | Базовый UI, CSS, конфигурация, HTTP-клиент и сгенерированные типы                                               |
| `src/mocks/`               | MSW, сценарии, изоляция и хранение демоданных, демонстрационные Summary и Comparison                            |
| `scripts/`, `src/test/`    | Генерация CSS и общая настройка тестов                                                                          |

Импорты идут от приложения к страницам, затем к виджетам, действиям, сущностям и общей инфраструктуре. Базовый UI остаётся независимым от сценария автомобиля. Mock-слой использует общий контракт и отдельное локальное хранилище. Продуктовые страницы получают данные через HTTP-клиент.

## Маршруты и состояние

| Путь           | Поведение                                                                                          |
| -------------- | -------------------------------------------------------------------------------------------------- |
| `/`            | Персональная выборка, быстрый ввод ссылки, удаление и выбор машин для сравнения                    |
| `/cars/new`    | Импорт с предпросмотром, ручной ввод по `?method=manual` и явное сохранение                        |
| `/cars/:carId` | Характеристики, расходы, преимущества, заметки, подтверждения и экономическое саммари              |
| `/comparison`  | Восстанавливает состав, загружает сравнение и позволяет исключать машины или открывать их карточки |
| `/ui-kit`      | Каталог базовых компонентов в development-режиме                                                   |
| `*`            | 404 и переход к выборке                                                                            |

Продуктовые маршруты используют белую поверхность и общий `Container wide` до 1460 px по содержимому, выровненный влево. Полноширинная верхняя панель отступает от краёв на 16–32 px. Dev UI Kit использует центрированный контейнер до 1120 px. При переходе layout переносит фокус в основное содержимое.

Ключи списка, карточек и саммари централизованы в сущности автомобиля. Запросы карточек и саммари получают `AbortSignal` от TanStack Query. Запрос списка завершает загрузку в кэш при кратковременном переключении маршрута или повторном монтировании. `entities/vehicle/mutations.ts` сериализует изменения одной карточки. После успешного изменения характеристик, расхода, преимущества или флага подтверждения отменяются незавершённые чтения и инвалидируются карточка, её саммари и выборка. Изменение заметки инвалидирует только карточку. Саммари сообщает об обновлении и даёт повторить запрос при ошибке.

Импорт загружает только предпросмотр. Форма автомобиля общая для добавления и редактирования. Редактирование передаёт изменённые поля через `PATCH /api/cars/{car_id}`. Подтверждения отправляются независимыми PATCH-запросами к той же карточке. Формы расходов, преимуществ и заметок используют `POST` коллекции и `PATCH`/`DELETE` её элемента. При неуспешном сохранении открытая форма сохраняет значения. Явный переключатель неизвестной суммы отправляет `null`, а введённый ноль отправляется как число. Ввод, выбор режима и выбранные ID остаются локальным UI-состоянием.

## Анонимная сессия

Граница продуктовых маршрутов загружает токен из `localStorage` или создаёт его через `POST /api/session`. Ключ разделён по режиму API, сценарию и базовому URL. Одновременные вызовы делят запрос создания. В окружении с Web Locks создание дополнительно сериализовано между вкладками того же origin.

Для защищённых запросов HTTP-клиент проставляет Bearer. При `401` граница закрывает продуктовые экраны и показывает выбор. Действие «Начать новую сессию» очищает сохранённый токен, состав сравнения и кэш данных прежней сессии, затем создаёт новую. При ошибке первоначального запроса можно повторить его. Токены находятся вне ключей TanStack Query и URL.

## Сравнение

`features/select-for-comparison/` ведёт единый состав для выборки и сравнения. Сохраняются уникальные внутренние ID в `localStorage`, по случайному локальному идентификатору сессии. При открытии сравнения список обновляется. В запрос попадают только ID из доступной выборки. Локальное удаление сразу исключает ID и убирает результаты с его участием из кэша. После внешнего удаления страница объясняет недоступность и позволяет убрать устаревшие отметки.

`POST /api/comparison` выполняется как запрос TanStack Query с `AbortSignal` и ключом состава. Загрузка начинается при наличии двух доступных автомобилей. Изменение характеристик, денежного фактора или подтверждения инвалидирует результаты с участием машины. При обновлении старые суммы скрываются. Сбой можно повторить, а при `404` сначала обновляется выборка.

`widgets/comparison-table/` сопоставляет ответ с автомобилями по `car_id`, сохраняя порядок API. Суммы, разницы, предупреждения и статус берутся из ответа. Нулевые разницы при равенстве подсвечиваются у всех соответствующих колонок. `null` отображается как недоступная разница. Компактный `thead` закрепляется при вертикальной прокрутке. Просторная таблица прокручивается вместе со страницей, а широкая относительно доступной области — внутри подписанного региона с закреплённой колонкой показателей. Ссылки на расходы, преимущества и заметки переносят фокус к соответствующим разделам карточки.

## Контракт и mock-данные

`npm run api:generate` обновляет `src/shared/api/schema.ts` из общего OpenAPI. HTTP-клиент обрабатывает JSON, типизированные ошибки, отмену и `204`. Для параметризованных путей клиент кодирует ID.

В mock-режиме worker запускается перед рендером. Обработчики покрывают операции выборки и карточки, вложенные ресурсы и саммари. Выданный mock-токен указывает на отдельную запись в `localStorage`. Каждая мутация записывает обновлённую выборку одной операцией, а Web Locks при наличии сериализует изменения одного токена. Чужой или отсутствующий ID машины либо записи даёт `404`. Неизвестный токен даёт `401`. Переключение на real использует тот же клиент и те же типы. MSW стартует только в mock-режиме.

`empty` создаёт пустую выборку, `seeded` заселяет сессию копией fixtures, `list-error` проверяет повтор загрузки. Импорт ищет синтетическую ссылку в `import-listings.json`. `mocks/summary.ts` рассчитывает одиночное саммари по общим правилам. Тест сопоставляет его с полями каждой машины в `calculation-tests.json`. В интерфейсе суммы и статус полноты берутся из `GET /api/cars/{car_id}/summary`. Карточка получает флаги из `GET /api/cars/{car_id}`.

В mock-данных изменение характеристики сбрасывает оба подтверждения. Явные флаги в том же PATCH применяются после сброса. Добавление, фактическое изменение или удаление денежной записи сбрасывает её группу. Заметки оставляют оба подтверждения и саммари прежними.

Формы денежных факторов принимают необязательный `factor_key` через настройку «Связать одинаковое оснащение». При редактировании значение сохраняется и при закрытой настройке. Mock проверяет точное совпадение после удаления крайних пробелов. В пределах одной машины он отклоняет повтор ключа в категории расхода, повтор ключа в преимуществах и пересечение между `missing_equipment` и преимуществом. При сравнении пересечение между машинами даёт `double_count` и разницы `null`.

Фотографии моделей выдаются только при создании новой seeded mock-сессии. Они берутся из `public/demo/vehicles/` и маркируются в интерфейсе. Выданные ранее карточки и общие fixtures сохраняют свои значения.

## Диагностика загрузки оценки

В обычном локальном Mock API три запроса `Summary` вернули `200` в новой сессии и после восстановления прежней выборки, включая хранилище с токеном без вспомогательного ключа `.scope`. Исторический сбой по скриншоту диагностировать нельзя без статусов и тел ответов из того запуска. Подстановка `503` для трёх запросов воспроизвела все сообщения, а повтор восстанавливал суммы без сброса выборки. Старый недействительный токен воспроизвёл отдельный сценарий `401` на запросе выборки.

Клиент теперь проверяет поля `Summary` и соответствие `car_id` после разбора JSON. Некорректный `200` отображается как ошибка. Ожидание сети, сетевой сбой, недоступный автомобиль и ошибка сервера имеют отдельные сообщения. Ключи запросов, конфигурация mock/real и область хранения сохранены. Регрессионный тест и проверка в Chrome используют отдельные демосессии.

В длинной браузерной регрессии карточки Chrome несколько раз сообщал об ошибке фонового обновления Service Worker MSW. Прямой запрос файла worker вернул `200`, а проверки обновления данных, сохранения и изоляции дошли до конца. В прогоне экранов этапа 6 и в регрессии сравнения это сообщение отсутствовало.

`mocks/comparison.ts` переиспользует одиночный расчёт. Тест Mock API сверяет все `items`, разницы, коды предупреждений и `provisional` по шести общим векторам. Семантика пограничных случаев описана в [интеграции с Backend](BACKEND_INTEGRATION.md). Дальнейшие изменения интерфейса перечислены в [бэклоге](BACKLOG.md).
