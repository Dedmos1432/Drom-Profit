# Архитектура Drom Profit Web

## Стек и слои

React 19 и TypeScript в строгом режиме. Vite собирает приложение, React Router ведёт клиентские маршруты. Базовые компоненты используют CSS Modules, общие CSS custom properties и Lucide React. Zod проверяет конфигурацию среды. MSW управляет локальными API-заглушками. Vitest и React Testing Library покрывают контракты базовых компонентов и HTTP-клиента.

| Каталог                                      | Ответственность                                                                |
| -------------------------------------------- | ------------------------------------------------------------------------------ |
| `src/main.tsx`                               | Проверка конфигурации, запуск MSW при необходимости и рендер React             |
| `src/app/`                                   | Маршруты, layout и общая композиция                                            |
| `src/pages/`                                 | Продуктовые заглушки в `product/` и developer UI Kit в `ui-kit/`               |
| `src/widgets/header/`                        | Шапка и основная навигация                                                     |
| `src/shared/ui/` и `src/shared/styles/`      | Универсальные UI-компоненты, CSS-токены, глобальные стили и типографика        |
| `src/shared/api/` и `src/shared/config/`     | Транспорт, типы OpenAPI и публичная конфигурация API                           |
| `src/mocks/` и `public/mockServiceWorker.js` | Worker и первые обработчики для mock-режима                                    |
| `src/test/`                                  | Настройка окружения тестов, тесты компонентов и транспорта лежат рядом с кодом |
| `scripts/`                                   | Генерация CSS из JSON-токенов                                                  |

Импорты между слоями идут от `app` к `pages`, `widgets` и `shared`. Страницы и виджеты используют `shared`, общий слой не импортирует продуктовые компоненты. `mocks` зависит от транспорта, сгенерированного типа и fixtures и загружается по решению точки входа. Алиас `@/` ведёт в `src/`. Выделяйте `features/` и `entities/`, когда появится переиспользуемая продуктовая логика.

## Маршрутизация

| Путь           | Поведение                                                     |
| -------------- | ------------------------------------------------------------- |
| `/`            | Заглушка персональной выборки                                 |
| `/cars/new`    | Заглушка добавления                                           |
| `/cars/:carId` | Заглушка карточки с идентификатором из маршрута               |
| `/comparison`  | Заглушка сравнения                                            |
| `/ui-kit`      | Каталог реальных компонентов только при `import.meta.env.DEV` |
| `*`            | 404 и переход в выборку                                       |

Шапка и контейнер общие, при переходе фокус переносится на область основного содержимого. UI Kit загружается отдельно в dev. Production-ветка не регистрирует его маршрут и ссылку.

## Состояние и дизайн-система

Ввод и взаимодействия UI Kit работают через нативные контролы и локальное состояние React. TanStack Query и React Hook Form добавляются при появлении реальных потребителей серверных данных и продуктовых форм. Context имеет смысл при подключении анонимной сессии. Отдельное глобальное хранилище на этом этапе не нужно.

Числовые и цветовые значения находятся в `docs/design-tokens.json`. Генератор разворачивает группы и ссылки в `src/shared/styles/tokens.css`. Компоненты используют эти переменные через CSS Modules. `Price` форматирует переданное значение в целых рублях, `Table` сохраняет нативную разметку и даёт широким данным собственную прокручиваемую область.

## Транспорт и Mock API

`npm run api:generate` обновляет типы из общего `shared/openapi.yaml` через openapi-typescript. Файл `schema.ts` — сгенерированный. Модели домена и ответа берутся из `components`, `paths` и `operations`.

`createApiClient` принимает базовый URL и функцию получения текущего токена. Клиент добавляет Bearer для переданного токена, отправляет и разбирает JSON, пропускает чтение тела при `204` и принимает `AbortSignal`. `ApiError` отличает HTTP-ошибку, сетевой сбой и некорректный успешный ответ. Отмена запроса передаётся вызывающему коду. Возвращаемый тип запроса указывается из сгенерированного контракта при подключении операции.

В mock-режиме worker запускается до рендера. Сейчас `POST /api/session` создаёт временный демонстрационный Bearer-токен, а `GET /api/cars` отвечает защищённой заглушкой из `demo-cars.json`. Необработанный запрос к настроенному `/api/` останавливается в mock-режиме. Заглушки экранов самопроизвольно к API не обращаются.

## Дальнейшее подключение P0

1. Подключить восстановление анонимной сессии и выборку к общему клиенту. Согласовать с backend сценарий потерянного или просроченного токена и CORS.
2. Добавить mock-обработчики импорта и CRUD по утверждённым моделям и fixtures. Предпросмотр, ручной ввод и подтверждение факторов собирать из переиспользуемых полей.
3. Подключить саммари и сравнение на основе серверных ответов. Использовать расчётные векторы, включая неизвестные суммы, равенство и двойной учёт. Представление отрицательного итога в одиночном Summary требует согласования состава серверных предупреждений.
