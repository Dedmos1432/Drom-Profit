# Архитектура Drom Profit Web

## Стек и слои

React, TypeScript в строгом режиме, Vite и React Router. Визуальные компоненты используют CSS Modules, общие CSS-переменные и Lucide. TanStack Query хранит серверные данные, React Hook Form и Zod обслуживают формы. MSW отвечает за Mock API.

| Каталог                    | Ответственность                                                                              |
| -------------------------- | -------------------------------------------------------------------------------------------- |
| `src/main.tsx`, `src/app/` | Конфигурация, запуск MSW, QueryClient, маршруты и общий layout                               |
| `src/pages/`               | Выборка, добавление, просмотр автомобиля, подготовка сравнения, 404 и development UI Kit     |
| `src/entities/session/`    | Восстановление токена, создание сессии и граница защищённых маршрутов                        |
| `src/entities/vehicle/`    | Типизированные вызовы и ключи запросов, схема валидации, форматирование характеристик и фото |
| `src/features/`            | Ввод ссылки, единая форма добавления, мутация сохранения и удаление с подтверждением         |
| `src/widgets/`             | Шапка и строка автомобиля в выдаче                                                           |
| `src/shared/`              | Базовый UI, CSS, конфигурация, HTTP-клиент и сгенерированные типы                            |
| `src/mocks/`               | MSW, сценарии, изоляция и хранение демоданных, демонстрационное саммари                      |
| `scripts/`, `src/test/`    | Генерация CSS и общая настройка тестов                                                       |

Импорты идут от приложения к страницам, затем к виджетам, действиям, сущностям и общей инфраструктуре. Базовый UI остаётся независимым от сценария автомобиля. Mock-слой использует общий контракт и отдельное локальное хранилище. Продуктовые страницы получают данные через HTTP-клиент.

## Маршруты и состояние

| Путь           | Поведение                                                                       |
| -------------- | ------------------------------------------------------------------------------- |
| `/`            | Персональная выборка, быстрый ввод ссылки, удаление и выбор машин для сравнения |
| `/cars/new`    | Импорт с предпросмотром, ручной ввод по `?method=manual` и явное сохранение     |
| `/cars/:carId` | Минимальная карточка сохранённого автомобиля                                    |
| `/comparison`  | Принимает выбранные ID через состояние маршрута и показывает статус подготовки  |
| `/ui-kit`      | Каталог базовых компонентов в development-режиме                                |
| `*`            | 404 и переход к выборке                                                         |

Продуктовые маршруты используют белую поверхность, плоские строки и функциональные панели. Dev UI Kit сохраняет свой фон. При переходе layout переносит фокус в основное содержимое.

Ключи списка, карточек и саммари централизованы в сущности автомобиля. Запросы карточек и саммари получают `AbortSignal` от TanStack Query. Запрос списка завершает загрузку в кэш при кратковременном переключении маршрута или повторном монтировании. Успешные мутации обновляют кэш и инвалидируют список. Импорт загружает только предпросмотр. Ввод, выбор режима и выбранные ID остаются локальным UI-состоянием. При неуспешном сохранении редактируемая форма остаётся смонтированной и сохраняет значения.

## Анонимная сессия

Граница продуктовых маршрутов загружает токен из `localStorage` или создаёт его через `POST /api/session`. Ключ разделён по режиму API, сценарию и базовому URL. Одновременные вызовы делят запрос создания. В окружении с Web Locks создание дополнительно сериализовано между вкладками того же origin.

Для защищённых запросов HTTP-клиент проставляет Bearer. При `401` граница закрывает продуктовые экраны и показывает выбор. Действие «Начать новую сессию» очищает сохранённый токен и запросы старой выборки, затем создаёт новую сессию. При ошибке первоначального запроса можно повторить его. Токены не используются как ключи TanStack Query и не выводятся в интерфейс.

## Контракт и mock-данные

`npm run api:generate` обновляет `src/shared/api/schema.ts` из общего OpenAPI. HTTP-клиент обрабатывает JSON, типизированные ошибки, отмену и `204`. Для параметризованных путей клиент кодирует ID.

В mock-режиме worker запускается перед рендером. Обработчики реализуют создание сессии, чтение выборки, импорт, сохранение, чтение карточки, удаление и саммари. Выданный mock-токен указывает на отдельную запись в `localStorage`. Каждая мутация записывает обновлённую выборку одной операцией, а Web Locks при наличии сериализует изменения одного токена. Чужой или отсутствующий ID даёт `404`, неизвестный токен — `401`. Переключение на real использует тот же клиент и те же типы, без старта MSW.

`empty` создаёт пустую выборку, `seeded` заселяет сессию копией fixtures, `list-error` проверяет повтор загрузки. Импорт ищет синтетическую ссылку в `import-listings.json`. Демонстрационный stub саммари находится в mock-слое. На продуктовой странице суммы отображаются только из ответа API.

## Открытые вопросы интеграции

- Сценарий истечения и восстановления анонимного токена, а также CORS для реального origin.
- Пакетное саммари для выборки. В текущем контракте это отдельный запрос на автомобиль.
- Нужны ли идентификатор идемпотентности для повторного POST после сетевого сбоя и ошибки валидации с указанием поля. Сейчас `Error` содержит общий код и сообщение.
- Представление серверных предупреждений об отрицательной скорректированной стоимости на одиночной карточке.

Следующий этап подключает редактирование сохранённого авто, расходы, преимущества, заметки и полноценную таблицу сравнения на общем контракте.
