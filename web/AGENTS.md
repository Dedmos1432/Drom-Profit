# Web — Xolopenya
Прочитай корневой AGENTS.md, docs/ и shared/openapi.yaml. На текущем этапе работай в feat/web-init, только web/.

- React, TypeScript, Vite; адаптивный интерфейс. Web использует собственную дизайн-систему на основе визуального аудита веб-версии Дрома. Android UI Kit и токены Dedmos не являются источником токенов Web.
- Реализуй выборку, импорт по ссылке с подтверждением, ручное добавление, карточку, формы расходов/преимуществ/заметок и сравнение двух и более автомобилей.
- Отдельный API client с переключением mock/real через конфигурацию. Mock воспроизводит согласованные ответы и состояния API. Для изменяемых демонстрационных данных допустим тестовый stub по правилам docs/calculation-rules.md, но не второй production-калькулятор.
- Сохраняй токен анонимной сессии между перезапусками, не выводи его в логи; не помещай секреты в VITE_* переменные. Настрой base URL, CORS согласуй с backend.
- Обрабатывай null, загрузку, пустую выборку, ошибки импорта, неподтвержденные расходы, предупреждения сравнения. Не выдавай предварительные суммы за окончательные.
- Готовность: локальный запуск, production build, проверка сценария на fixtures, адаптивность и инструкция запуска. Не изменяй android/ и backend/.

## Визуальное оформление Web

- Основные документы — [дизайн-система](docs/DESIGN_SYSTEM.md), [токены](docs/design-tokens.json) и [спецификация компонентов](docs/UI_COMPONENTS.md). [Визуальный аудит](docs/DROM_VISUAL_AUDIT.md) содержит измерения, наблюдения и ограничения исследования.
- Приоритет — визуальная согласованность с веб-версией Дрома. Реализуй веб-паттерны собственными средствами, с собственными компонентами и ресурсами.
- После утверждения дизайн-системы используй её токены и компоненты для новых экранов. Переиспользуй существующий компонент, когда он покрывает задачу. Применяй существующие токены для цветов, размеров и отступов. Новое визуальное решение обоснуй и зафиксируй в документации дизайн-системы.
