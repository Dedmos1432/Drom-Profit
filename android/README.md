# Дром Профит для Android

Откройте каталог android в Android Studio. Для сборки нужны JDK 21, Android SDK Platform 37 и Build Tools 36.0.0. Для установки нужны Platform Tools и устройство или эмулятор. Минимальная версия приложения — Android 8.0 (API 26).

## Запуск и проверка

Из каталога android в PowerShell:

~~~powershell
.\gradlew.bat :app:assembleDebug "-PdromProfitDemoScenario=showcase"
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug
~~~

APK находится в app/build/outputs/apk/debug/app-debug.apk. Установите его через adb install -r app/build/outputs/apk/debug/app-debug.apk или запустите конфигурацию app в Android Studio. Если Java отсутствует в PATH, задайте JAVA_HOME на JDK 21 или встроенную JBR Android Studio.

Для инструментальной проверки Room с подключённым устройством или запущенным эмулятором выполните .\gradlew.bat :app:connectedDebugAndroidTest.

## Демо-сценарии

В debug без URL API используются локальные данные. Активный сценарий выбирается параметром -PdromProfitDemoScenario.

| Сценарий | Выборка при первом запуске |
| --- | --- |
| empty | Пустая, используется по умолчанию |
| seeded | Три синтетические Camry из общих fixtures |
| showcase | Пять машин из общих `demo-showcase.json` и `demo-showcase-assessments.json` с фото, расходами, преимуществами и заметками |
| list-error | Первый запрос выборки завершается ошибкой. «Повторить» загружает список |

Выборка и отметки для сравнения сохраняются между запусками и привязаны к сценарию. Сборка с прежним параметром -PdromProfitDemoEmpty=true использует отдельную демовыборку.

1. На главной вставьте https://auto.drom.ru/demo/1.html или https://auto.drom.ru/demo/101.html, откройте предпросмотр и сохраните автомобиль. Для ручного добавления обязательны марка, модель и цена от 1 до 1 000 000 000 000 ₽.
2. Откройте карточку, смените снимок по миниатюре и добавьте расход, преимущество или заметку. Проверьте разницу между нулём и неизвестной суммой. Отметьте рассмотренные группы.
3. На главной выберите две или больше машин по одной или нажмите «Выбрать все». В сравнении пролистайте таблицу горизонтально и вертикально. Проверьте ссылки к записям и действие «Исключить», которое меняет состав сравнения. Удаление машины доступно отдельно в выборке.
4. Для ошибки импорта подойдёт https://auto.drom.ru/demo/404.html. Форма оставляет ссылку и позволяет повторить попытку либо перейти к ручному вводу.

Фотографии витрины хранятся в debug-ресурсах. Авторы, исходники и лицензии указаны в [атрибуции](app/src/debug/assets/demo/vehicles/ATTRIBUTION.md).

## Подключение backend

Для эмулятора с API на порту 8000 компьютера:

~~~powershell
.\gradlew.bat :app:assembleDebug "-PdromProfitApiBaseUrl=http://10.0.2.2:8000/"
~~~

Для телефона по USB настройте adb reverse tcp:8000 tcp:8000 и соберите debug с -PdromProfitApiBaseUrl=http://127.0.0.1:8000/. Debug HTTP доступен для `10.0.2.2` и `127.0.0.1`. Для release необходим настроенный HTTPS endpoint. Retrofit обращается к маршрутам /api общего OpenAPI. Базовый адрес может включать префикс пути.

При первом обращении клиент создаёт анонимную сессию и хранит Bearer-токен в приватном хранилище. При ответе 401 новая сессия создаётся по явному действию пользователя. Сетевой режим показывает серверные итоги и предупреждения. В debug относительные пути `/demo/vehicles/…` разрешаются в комплектные JPG без Web-сервера. При недоступности кадра видна заглушка, остальные кадры доступны. Загрузка абсолютных ссылок ограничена настроенным origin API. Доступность импорта зависит от источника бэкенда.

## Интерфейс и структура

Референс — [веб-коммит 986d4d3](https://github.com/Dedmos1432/Drom-Profit/commit/986d4d31727a96b5dd57ddfc2cc9e95f799c10ac). Мобильная версия использует белую поверхность, синие действия, серую панель быстрого добавления и красный акцент для бренда и удаления. Главная объединяет импорт и выборку. Карточка объединяет галерею, характеристики, записи и оценку. Таблица сравнения закрепляет названия столбцов и подписи строк.

| Пакет | Ответственность |
| --- | --- |
| presentation/screens | Нативные Compose-экраны и Preview |
| presentation/viewmodels | Состояния и действия экранов через StateFlow |
| presentation/components и presentation/navigation | Общий UI и переходы |
| domain/repository и domain/usecases | Контракты и сценарии на Kotlin |
| data/local | Room, зеркала серверных карточек и сохранение состава сравнения |
| data и di | Retrofit, демо-репозиторий, приватная сессия и связывание слоёв |

В сетевом режиме расчёт выполняется на backend. Room хранит полученную выборку отдельно для каждой анонимной сессии и адреса API. API-клиент передаёт только изменённые поля PATCH, включая явный null при очистке допустимого поля. При редактировании машины изменение основного снимка сохраняет остальные кадры. Действие «Очистить галерею» применяется при сохранении формы. Room 1 → 2 сохраняет существующие записи и хранит полный порядок кадров из detail.
