# Drom Profit — общие инструкции для ИИ-агентов

## Контекст и источник требований
Проект стажировки Дром Тех: персонализированное экономическое сравнение подержанных автомобилей, самостоятельно отобранных покупателем. Не рыночная оценка и не диагностика. Согласованный объем — `docs/MVP.md`; формулы и пограничные случаи — `docs/calculation-rules.md`; архитектура и ответственность — `docs/architecture.md`; контракт — `shared/openapi.yaml`. Данные для разработки — `shared/fixtures/`. При противоречии остановись на спорном изменении, сообщи команде; не меняй контракт самовольно.

## Правила работы
- Перед изменениями проверь `git status`, текущую ветку, структуру и существующие файлы; прочитай инструкции своей директории. Не удаляй и не переписывай чужие наработки, не сбрасывай незакоммиченные изменения.
- Работай в назначенной feature-ветке, только в своей зоне. Общие файлы, контракт, зависимости другого модуля, инфраструктура — через согласованный PR. Не выполняй merge в main и не делай force push.
- Стек: Android Kotlin/Compose; Web React/TypeScript/Vite; сервер Python/FastAPI/Pydantic/SQLAlchemy/SQLite. Экономическая модель только на сервере. Модуль импорта — внутри backend, не микросервис.
- Не добавляй функциональность вне MVP без согласования. Не используй реальные отчеты, персональные данные, токены или ключи в репозитории. Не обращайся к Дрому автоматически без согласованного доступа; не обходи ограничения.
- Используй целые рубли, null для неизвестных данных, явные статусы полноты. Не выдумывай характеристики и не называй скорректированную стоимость рыночной ценой.
- Сначала обеспечь рабочий основной сценарий, затем улучшай интерфейс. Добавляй минимально необходимые зависимости. Выполни сборку и целевые тесты; если не удалось, сообщи причину.
- В финале перечисли измененные файлы, команды запуска, результаты проверок, ограничения и вопросы интеграции. Не утверждай, что тесты прошли, если не запускал.
