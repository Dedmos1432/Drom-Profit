# Проверка сохранённых объявлений Дрома

На этапе 8.4 локально проверены шесть сохранённых пользователем HTML-страниц настоящих объявлений. Согласование автоматизированного доступа к источнику остаётся открытым. В штатном запуске включён Demo Provider, внутренняя сеть Docker сохранена. [Статусы INT-07, INT-14 и INT-15](INTEGRATION_BACKLOG.md)

## Что нужно от владельца источника

Уточнить доступные варианты в порядке предпочтения — официальный или внутренний API, тестовый источник команды, разрешённые сохранённые HTML или JSON, затем прямой HTTPS при согласованном автоматизированном доступе. Для API нужны согласованное описание ответа и условия доступа. Для HTTPS нужны точные хосты и разрешённые перенаправления, допустимые частота и объём запросов, условия использования данных и фотографий.

Достаточно 5–10 обезличенных образцов. Желательны разные марки, годы, города и коробки, бензин, дизель и гибрид или электромобиль при наличии. Включите частичную карточку, несколько фото, десктопную и мобильную разметку, удалённое или недоступное объявление и допустимое перенаправление, если такие примеры есть.

Для каждого образца приложите:

- Обезличенный исходный URL, ID и цепочку ответов до конечного URL с HTTP-статусами, `Location`, `Content-Type`, известной кодировкой и временем сохранения.
- Разрешённый сохранённый HTML либо минимальный обезличенный HTML с относящимися к карточке JSON-LD и Open Graph. Для отдельного API приложите разрешённый JSON и описание полей. CLI ниже воспроизводит HTML-ответы текущего провайдера.
- Отображаемую цену с валютой. Для числовых характеристик нужны значение, исходная единица и источник поля. Отметьте отсутствующие данные и отдельно поля с неподтверждённой семантикой.
- Для фотографии укажите главный снимок и права использования. Для рыночной оценки приложите подтверждённое поле источника, его семантику, единицы и пример с отсутствующим значением.

Храните образцы и результаты их просмотра вне репозитория в согласованном хранилище. Передавайте минимум разметки, достаточный для воспроизведения. Уберите данные продавцов, идентификаторы профилей, cookies, авторизационные данные и подписанные параметры URL. При обезличивании сохраняйте согласованность ID и путей во всех связанных объектах.

## Локальное воспроизведение

Для каждого образца создайте JSON-манифест рядом с сохранённым HTML. Если есть HTTP-метаданные, используйте `responses`. Ниже пример для существующего **синтетического** HTML. Для разрешённого HTML укажите `kind: "saved_html"`. `body_file` указывается относительно манифеста или абсолютным локальным путём.

```json
{
  "kind": "synthetic",
  "request_url": "https://vladivostok.drom.ru/toyota/camry/12345678.html",
  "allowed_hosts": ["vladivostok.drom.ru"],
  "redirect_hosts": [],
  "responses": [
    {
      "url": "https://vladivostok.drom.ru/toyota/camry/12345678.html",
      "status": 200,
      "headers": {"Content-Type": "text/html; charset=utf-8"},
      "body_file": "synthetic_listing.html"
    }
  ],
  "expected_fields": {
    "brand": {"state": "observed", "value": "Toyota", "origin": "JSON-LD Car.brand.name"},
    "price": {"state": "observed", "value": 1200000, "origin": "JSON-LD Offer.price (RUB)"},
    "market_valuation": {"state": "absent", "origin": "синтетическая страница"},
    "fetched_at": {"state": "unconfirmed"}
  }
}
```

Для перенаправления перечислите ответы по порядку. У промежуточных ответов укажите статус и `Location`. Для отрицательного сценария задайте `expected_error`, например `listing_unavailable` для сохранённого ответа 404. Тело нужно только для 200. Для времени записи исходного ответа можно указать `captured_at`. Поле `fetched_at` в результате относится к локальному вызову провайдера.

Для сохранённых браузером страниц без HTTP-метаданных вместо `responses` и `request_url` используйте `document`. Укажите канонический адрес из HTML и фактическую кодировку файла:

```json
{
  "kind": "saved_html",
  "allowed_hosts": ["auto.drom.ru"],
  "document": {
    "canonical_url": "https://auto.drom.ru/example/model/12345678.html",
    "body_file": "approved-page.html",
    "encoding": "cp1251"
  }
}
```

CLI использует тот же разбор HTML и оставляет `responses` пустым. Канонический адрес служит для сверки ID. `fetched_at` указывает время локального разбора.

Из каталога `backend/` выполните:

```powershell
python -X utf8 -B -m tests.listings.review_saved_listing C:\path\to\capture.json
```

В режиме `responses` CLI передаёт локальные ответы существующим SafeHttpClient и DromHtmlProvider. Все обращения транспорта и DNS подменены. Такой прогон проверяет логику обработки сохранённых статусов, форматов, URL и тела. Он не измеряет доступность источника, реальный DNS, TLS и сетевые тайминги.

После успешного разбора JSON-отчёт содержит таблицу из 18 строк с ожидаемым и фактическим значением, статусом и путём или источником поля. `match` означает совпадение, `absent` — подтверждённое отсутствие, `missing` — эталонное значение есть, а Parser его не вернул, `mismatch` — различие, `unconfirmed` — требуется подтверждение семантики, `unverified` — эталон не задан. Отчёт также содержит записанные HTTP-метаданные, код Parser и отметку по каждому воспроизведённому шагу. Код выхода `1` означает расхождение с эталоном или неполное воспроизведение, `2` — проблему входного манифеста или чтения файла. `ok: true` относится к заданным проверкам.

## Что подтверждено локально

| Поля | Реализация и синтетическая проверка |
|---|---|
| `source`, `listing_url`, `listing_id`, `fetched_at` | `drom`, канонический URL, идентификация по URL и структурированным данным, UTC-время вызова. |
| `brand`, `model`, `year`, `trim` | Выбор объекта Car, Vehicle или Product по ID/URL. Поля brand/manufacturer, model, варианты полей года и vehicleConfiguration. |
| `price` | Цена Offer применяется при явной валюте RUB/RUR. Отсутствие подтверждённой положительной цены даёт `parse_error`. |
| `mileage_km`, `engine_volume_l`, `power_hp` | Проверены км и тыс. км, литры и см³, л. с. и кВт. Для неизвестных и противоречивых единиц результат `null`. |
| `fuel_type`, `transmission`, `drive_type`, `city` | Используются поля автомобиля, двигателя и предложения. Синтетическая карточка возвращает топливо, коробку, привод и город. |
| `image_url` | Первый допустимый структурированный снимок, затем запасной Open Graph. Проверены относительные URL, порядок, уникальность и отсутствие снимка. Сервер не загружает тело фото при импорте. |
| `market_valuation` | HTML-провайдер возвращает `null`. Для заполнения нужно подтверждённое поле согласованного источника. |

### Шесть сохранённых страниц

Исходный `d2f76a5` отклонил все шесть. Один URL отклонялся из-за `~`. В остальных пяти объектах Car отсутствовали собственный ID и адрес. После сопоставления `Offer.url` и добавления видимых полей обработаны все шесть страниц. Разметка четырёх страниц использована при разработке, две были контрольными. Все файлы прочитаны как Windows-1251, строгая проверка UTF-8 не прошла. HTTP-статусы, исходные заголовки и конечный сетевой URL неизвестны.

- Марка, модель, год и пробег получены из JSON-LD. Цена с валютой получена из Offer и сверена с ценой, видимой на странице. ID согласован с URL предложения, canonical и Open Graph.
- Комплектация, мощность, двигатель, привод и коробка извлекаются из строк `bulletin-specifications`. Город получен из блока описания. На четырёх страницах строки комплектации нет, результат равен `null`.
- 136 ссылок основной галереи совпали по порядку с `gallery.photos.images` из встроенного JSON. Снимки не загружались. Публичный результат содержит один URL.
- В `priceWidgetData.goodDealConfig` есть `price`, числовой `marketPrice` и отдельный `dealType`. `price` совпадает с ценой объявления. `averagePriceWidget` пуст на всех шести страницах. Публичная семантика `marketPrice` не подтверждена, поэтому `market_valuation` остаётся `null`. `candyConfig` содержит служебные настройки и не используется для характеристик.

Из 108 полей 86 сверены с данными объявления, 12 служебных значений задаёт прогон (`source` и `fetched_at`), в четырёх полях подтверждено отсутствие комплектации, в шести отдельно отмечена неподтверждённая рыночная оценка.

Локальный стенд использует существующий Core-адаптер с Parser и подставным транспортом. Обезличенные фрагменты для стенда содержат только характеристики, цену, ссылки и необходимую разметку. Внешние запросы браузера блокировались до отправки. Core вернул 18 полей и HTTP 200 для всех шести локальных фрагментов. Chrome подтвердил предпросмотр, редактирование, отдельное сохранение в PostgreSQL, Summary и Comparison для двух карточек. Штатный запуск остаётся demo.

## Переход к сетевой проверке

После согласования проверить образцы локально и сверить с отображаемыми данными. Для сетевого стенда отдельно согласовать конфигурацию исходящего DNS и HTTPS к разрешённым хостам, сохранив внутреннюю сеть PostgreSQL, loopback-публикацию, UID контейнера и ограничения Parser. Текущая проверка защищённого клиента основана на подставном транспорте и не подтверждает работу DNS, TLS или таймингов на стороне Дрома. Затем проверить запуск провайдера в изолированном Compose-проекте, пять REST-кодов, Web-предпросмотр, явное сохранение и сравнение по двум разрешённым ссылкам. [Требования к сетевому стенду](INTEGRATION_BACKLOG.md#подготовка-к-int-14-и-int-15)
