# Архитектура и распределение работ
Android (Kotlin/Compose) и Web (React/TypeScript/Vite) → REST JSON → FastAPI → SQLAlchemy/SQLite. Внутри backend — CRUD, сессии, калькулятор, сравнение и listings provider. Один backend, без микросервисов. PostgreSQL при необходимости позже. Развертывание Docker Compose — после минимального рабочего сценария.

## Контракт

В OpenAPI 0.3.0 предпросмотр импорта и детальная карточка передают упорядоченные `image_urls` и основное `image_url`. Core хранит массив в колонке PostgreSQL `cars.image_urls`. Список читает только основное фото, а расчётные ответы содержат денежные данные. [Контракт фотогалереи](PHOTO_GALLERY_CONTRACT.md)
`shared/openapi.yaml` — проект общего контракта. JSON snake_case; nullable поля явно null; идентификаторы внутренних сущностей строковые, не равны ID объявления. Bearer токен анонимной сессии; клиент хранит его между запусками. Сервер проверяет принадлежность каждого объекта сессии; чужие ID возвращают 404. Нет синхронизации устройств. Импорт POST /api/cars/import возвращает preview ListingData без сохранения; POST /api/cars сохраняет подтвержденные данные. Для ручного ввода source=manual. Сравнение POST /api/comparison принимает выбранные car_ids.

Импортер: async import_listing(url: str) -> ListingData; не зависит от БД, вызывается backend. Fixture provider до согласования реального доступа. Ошибки переводит в HTTP Core Backend. Не смешивать demo с реальным источником. Реальный URL и изображения только при согласованном доступе; не обходить защиту. Не хранить приобретенные отчеты в git.
