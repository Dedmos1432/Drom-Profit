# Drom Profit — спецификация MVP v0.1
Статус: состав данных согласован; технические детали API и правила пограничных случаев — стартовое предложение для review команды.

## Цель и гипотеза
Целевой сегмент: самостоятельные покупатели подержанных автомобилей для личного использования на финальном этапе выбора. Если дать им возможность добавить отобранные объявления, дополнить собственными сведениями о вложениях и преимуществах и получить экономическое сравнение, им будет проще аргументировать выбор.
Основание: ДЗ 5, стр. 6 — 10 из 17 (58,8%) затруднялись оценить соответствие цены состоянию/истории; 10 из 17 (58,8%) — расходы на ремонт и обслуживание; 14 из 17 (82,4%) рассматривали два и более автомобиля. Это сигналы небольшой выборки, а не подтверждение гипотезы MVP.

## P0 — основной сценарий
1. Анонимная сессия, персональная сохраняемая выборка.
2. Вставка ссылки Дрома → получение доступных характеристик → подтверждение/редактирование → сохранение. При ошибке — ручной ввод; до разрешения на доступ — явно маркированный demo-источник.
3. Просмотр, изменение и удаление автомобилей.
4. Добавление/редактирование/удаление расходов, преимуществ и заметок; явное подтверждение полноты сведений.
5. Саммари автомобиля и сравнение 2+ выбранных машин, разница между предложениями, предупреждения. Web и Android используют одинаковые серверные результаты.

## Состав данных
Автоматические: марка, модель, год, цена, пробег, комплектация, тип и объем двигателя, мощность, коробка, привод, город, основная фотография, оригинальная ссылка, рыночная оценка Дрома (при доступности). Служебные: listing_id, источник (drom/demo/manual), время получения. Все недоступные поля null; для сохранения карточки обязательны марка, модель и цена.
Пользовательские: необходимые ремонтные работы и их предполагаемая стоимость, ТО, дополнительное оснащение и его персональная ценность, сведения из отчета, результаты осмотра, недостатки без необходимости устранения, произвольные заметки.
Расчетные: сумма вложений, сумма преимуществ, предполагаемые затраты, скорректированная стоимость, разница между предложениями, статус полноты.

## Не входит в P0
P1: исследование загрузки скачанного отчета и извлечения сведений с подтверждением пользователем; возможные шаблоны расходов, обновление объявления, отдельный сценарий торга. P2: прямая интеграция с отчетами/Избранным, учетные записи и синхронизация между устройствами, экспорт. Не реализуем автоматическую диагностику, автоматические штрафы за события истории, оценку ремонта, собственную рыночную оценку, монетизацию, ИИ внутри продукта, iOS.

## Критерии готовности
Оба клиента запускаются и проходят основной сценарий с общим backend; данные сохраняются, сессии изолированы; импорт на разрешенном источнике либо явно обозначенный demo + ручной ввод; расчеты проходят общие тесты; отсутствующие данные не маскируются; ошибки доступны пользователю; README запуска, APK и доступная тестовая web-сборка. Реальный импорт — отдельный приемочный пункт, если пока доступен лишь demo.

## Проверка гипотезы (предлагаемый план)
7 представителей сегмента: дать задачу сравнить 2–3 автомобиля, сначала обычным способом, затем с продуктом (по возможности менять порядок между респондентами). Зафиксировать время, ошибки, самостоятельность, объяснение решения, готовность внести расходы и оценку полезности. Ориентиры пилота: 6/7 завершают сценарий, 5/7 понимают результат, 5/7 видят пользу, 5/7 готовы использовать. Это качественный пилот, не статистическая валидация.
