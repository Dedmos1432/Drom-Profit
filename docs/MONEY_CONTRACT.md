# Денежный контракт MVP

Этот документ задаёт действующие правила денежных значений. Он имеет приоритет над историческим [предложением и аудитом](MONEY_CONTRACT_PROPOSAL.md). OpenAPI 3.0.3 сохраняется. Версия API повышена с `0.1.0` до `0.2.0`: допустимые денежные значения сужены, поэтому для MVP до 1.0 это несовместимое изменение с новой младшей версией.

## Формат и границы

Единица — целый рубль. Технический предел `L = 1 000 000 000 000` ₽. Типы: Python `int`, PostgreSQL `BIGINT`, OpenAPI `integer/int64`, TypeScript `number`, Kotlin `Long` или `Long?`.

| Поле | Минимум | Максимум | Nullable |
|---|---:|---:|---|
| `Car.price`, `CarInput.price`, `CarPatch.price`, `listing_price` | 1 | L | Нет |
| `ListingData.price` | 1 | L | Да |
| `market_valuation` | 1 | L | Да |
| `Expense.amount`, `Benefit.amount` | 0 | L | Да |
| `total_expenses` (R), `total_benefits` (B) | 0 | L | Нет |
| `acquisition_cost` (C) | 1 | 2 000 000 000 000 | Нет |
| `adjusted_cost` (E) | −999 999 999 999 | 2 000 000 000 000 | Нет |
| `difference_from_min` | 0 | 2 999 999 999 999 | Да при `double_count` |

REST принимает десятичные целочисленные JSON-литералы. `2` допустим, `2.0`, `1.5`, `1.0000000000000001`, `1e3`, `"1000"` и логические значения запрещены. `-0` имеет значение 0. Клиенты отправляют 0 без минуса. При PATCH отсутствие свойства сохраняет прежнее значение, явное `null` очищает nullable-поле. Нулевая сумма фактора известна и отличается от неизвестного `null`. Требуемая при создании сумма фактора передаётся явно, даже если неизвестна. Денежные правила оставляют прежние ограничения года, пробега, мощности и объёма.

Формулы остаются `C=P+R`, `E=C−B`, `difference_from_min=E−min(E)`. При `1≤P≤L` и `0≤R,B≤L` диапазон E равен `1−L…2L`, а разница не выше `3L−1`. Эти пределы гарантируют точность JavaScript Number. `negative_adjusted_cost`, `provisional`, неизвестные суммы, равные E и `double_count` сохраняют согласованную семантику. Рыночная оценка не участвует в формулах. [Правила расчёта](calculation-rules.md) · [OpenAPI](../shared/openapi.yaml)

## Запись, транзакции и ошибки

- Core валидирует диапазон и точный тип отдельных значений в Pydantic. Корректный целочисленный литерал вне диапазона или сумма группы выше L возвращают `422 amount_out_of_range`. Некорректный тип, синтаксис или структура возвращают `422 validation_error`. Структурная ошибка имеет приоритет при одновременном нарушении. Ответ сохраняет поля `code` и `message`.
- Core проверяет владельца, блокирует карточку под `FOR UPDATE` в `READ COMMITTED` и читает текущую группу после блокировки. POST проверяет сумму с новой записью. PATCH вычитает прежнее значение редактируемой записи. Изменение и сброс соответствующего подтверждения фиксируются вместе. Отказ сохраняет записи, флаги и сессию. Удаление не увеличивает сумму. Повторный PATCH без изменений сохраняет подтверждение.
- PostgreSQL контролирует отдельные столбцы именованными `CHECK`. SQL `NULL` разрешён только в nullable-полях. Другой писатель должен соблюдать блокировку карточки и проверять агрегаты в той же транзакции. Чтение сохраняет границы сессии и согласованный снимок этапа 8.6.1. [Core](../backend/app/api/car_items.py) · [SQLAlchemy](../backend/app/models.py) · [Жизненный цикл соединения](BACKEND_PERFORMANCE.md)
- Web валидирует текст до преобразования в `Number`, а сетевые суммы проверяет по исходным токенам с помощью `lossless-json` и по схемам DTO до кэша. В формах допустимы целые цифры и группировка по три цифры обычным или неразрывным пробелом. При ошибке форма сохраняет правки, сессия сохраняется и запрос автоматически не повторяется. Mock проверяет те же литералы, диапазоны и агрегаты перед записью. [Точный разбор Web](../web/src/shared/api/money.ts) · [Mock](../web/src/mocks/vehicle-writes.ts)

## Предпросмотр импорта

Распознанное объявление с корректной ценой 1…L возвращает цену. При действительном отсутствии цены распознанный автомобиль возвращается с `price: null`. Для сохранения нужно явно указать положительную цену. Нераспознанная структура, неверная или противоречивая цена, неподдерживаемая валюта и сумма вне диапазона дают `502 parse_error`. Проверки идентичности Car/Offer, canonical, ID и распознавание блокировки действуют и для страниц без цены.

Parser трактует денежное число JSON-LD точно через `Decimal`. Он принимает однозначную целую цену в рублях, включая поддерживаемую текстовую запись из 13 цифр. Некорректная, нулевая, противоречивая, неподтверждённая или чрезмерная рыночная оценка при импорте становится `null`. Известное недопустимое значение диагностируется без числа, URL и данных продавца. `priceWidgetData.goodDealConfig.marketPrice` не используется. При ручном вводе действует строгий диапазон и ответ 422. Запуск по умолчанию использует Demo Provider. [HTML Parser](../backend/app/services/listings/html_parser.py) · [Офлайн-проверка](REAL_LISTING_VALIDATION.md)

## Проверка старых данных и миграция

1. Перед выпуском выполните `python -m app.money_audit` в каталоге `backend/` с `DROM_DATABASE_URL` согласованного снимка или базы и учётной записью только чтения. Команда использует `REPEATABLE READ READ ONLY`, выводит только количества и завершает работу с кодом 1 при нарушениях. Она проверяет отдельные значения, R/B, небезопасные для JavaScript деньги и ширину диапазона E внутри сессии.
2. При нарушениях остановите релиз до согласованной корректировки данных. Сохраните исходные значения и повторите аудит после корректировки. Автоматическое обрезание, удаление и замена сумм исключены.
3. Остановите старые Backend workers и других писателей перед окончательной проверкой. Примените `python -m alembic upgrade head`. Ревизия `0002_money_contract` сама блокирует записи в три таблицы, повторяет аудит в транзакции и добавляет четыре именованных ограничения. При отказе транзакция оставляет прежнюю ревизию и суммы. Прямые запросы других писателей требуют соблюдения того же агрегатного инварианта.
4. Запустите Backend 0.2.0 и соответствующий Web. Проверьте OpenAPI и общий REST-набор. Android выпускается после своей проверки. Старые клиенты могут отправить ранее допустимые суммы и получить 422. При согласованном откате `alembic downgrade 0001_core` снимает новые проверки, сохраняя суммы. Код и схему откатывайте согласованно. [Инструмент аудита](../backend/app/money_audit.py) · [Ревизия Alembic](../backend/migrations/versions/0002_money_contract.py)

## Android

Денежные поля генерируются как `Long` или `Long?`. Перед `toLongOrNull()` проверяйте текст и диапазон, при JSON-декодировании сохраняйте сведения об исходной записи. Запретите `Float` и `Double` для денег. Для PATCH требуется состояние «не передавать поле» отдельно от состояния «передать null». Если генератор использует `Long? = null` для обоих состояний, используйте отдельную форму PATCH или явный сериализатор. Отображайте отрицательный E и nullable-разницу, показывайте `422 amount_out_of_range` без сброса формы и сессии. Экономические результаты поступают из Core. Проверка DTO/Retrofit-сериализатора, двух режимов nullable PATCH и debug APK входит в INT-17.
