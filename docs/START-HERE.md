# Как добавить этот комплект в существующий репозиторий
Архив содержит только инструкции, спецификацию, контракт и fixtures. Не содержит готового приложения и не заменяет имеющийся UI Kit. Приватный репозиторий не проверялся и не изменялся.

1. В корне локального Drom-Profit выполнить `git status`. Если есть незакоммиченная работа, не терять ее: сохранить в своей ветке/коммите либо использовать отдельный чистый клон. Проверить имя основной ветки.
2. На чистой копии: `git switch main`, `git pull --ff-only origin main`, `git switch -c chore/project-setup` (если основная ветка называется иначе, использовать ее).
3. Распаковать архив во временный каталог и перенести содержимое `drom-profit-setup/` в корень Drom-Profit. При совпадении имен сравнить и объединить файлы вручную; ничего не перезаписывать автоматически. `docs/README.template.md` — заготовка, а не замена существующего README.md.
4. Проверить `git status` и `git diff`. Добавить только файлы пакета, сделать коммит `docs: define MVP and agent contracts`, отправить ветку и создать PR в основную ветку. Проверить структуру с Dedmos и согласовать API и правила пограничных случаев.
5. После merge каждый обновляет свою локальную копию. Если рабочая ветка уже существует — аккуратно интегрировать main в нее; не создавать ее заново и не сбрасывать историю. Новые ветки создавать от обновленного main.

## Задачи агентам
- Dedmos: продолжи существующий UI Kit; прочитай android/AGENTS.md и подготовь Android-сценарий на mock API, не ломая текущий код.
- Xolopenya: прочитай web/AGENTS.md, реализуй Web-сценарий на fixtures и API client, затем подключи backend.
- №3: прочитай backend/AGENTS.md, согласуй OpenAPI и интерфейс импортера, реализуй Core Backend и тесты.
- №4: прочитай backend/app/services/listings/AGENTS.md, реализуй fixture provider и тесты; реальный источник только после разрешения.

## Вопросы перед интеграцией
- Разрешенный источник данных объявлений, тестовые страницы/API и фотографии — технический наставник.
- Формат UI Kit и общие дизайн-токены — Dedmos и Xolopenya.
- API и правила неполноты/двойного учета — review всех разработчиков.
- Хостинг, HTTPS и настройка CORS — Core Backend + Web.
- Образцы скачанных отчетов — отдельная задача P1, не блокирует P0.
