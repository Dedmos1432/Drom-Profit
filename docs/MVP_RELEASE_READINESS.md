## Проверка состава и ограничения

Проверены имена файлов и типовые признаки токенов и ключей в текущем дереве и коммитах между `origin/main` и `HEAD`. Совпадений по этим признакам и посторонних локальных env-файлов, APK, результатов сборки или архивов не обнаружено. `.env.example` содержат пустые значения для локальных секретов. Из HTML в истории PR присутствуют страницы Web и тестовый синтетический образец Parser. Демо-объявления и записи в fixtures обозначены как синтетические, изображения витрины сопровождаются атрибуцией. Локальная подготовка использовала собственную сессию и отдельную БД.

Сетевой импорт реальных объявлений и использование оригинальных фотографий Дрома ожидают письменного согласования. Семантика рыночной оценки ещё уточняется. Автоматическая обработка отчётов, пользовательские аккаунты, межплатформенная синхронизация и справочник `factor_key` находятся за пределами текущего показа. Отдельный функциональный аудит Web отложен до обратной связи лида. Историческое предупреждение React о двух одинаковых ключах в предпросмотре остаётся в наблюдениях витрины. Прежняя проверка подтвердила сохранение карточки при этом предупреждении. ## Условия слияния в main

1. Согласовать Web-объём PR с руководителем проекта. После ревью подготовить документальные правки к публикации в `integration/mvp`.
2. Перед отправкой заново сверить SHA `main` и состав диффа. Сохранить границу Web MVP и отдельную ветку Android.
3. Подтвердить smoke на том же составе изменений. При появлении функциональных правок прогнать затронутые регрессии.
4. Получить согласованный review и обязательные проверки репозитория. Вопросы APK, сетевого импорта, рыночной оценки, рабочей БД и эксплуатационных порогов продолжать отдельными задачами.
